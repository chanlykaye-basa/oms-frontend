# Commit - OMS Frontend

커밋 컨벤션에 따라 변경사항을 커밋합니다.

## 입력

$ARGUMENTS

## 절차

### 1. 컨벤션 로딩

`docs/commit-convention-frontend.md`를 읽고 컨벤션을 파악합니다.

### 2. 변경사항 분석

- `git status`로 변경/추가/삭제된 파일 확인
- `git diff --staged`로 스테이징된 변경사항 확인
- 스테이징된 파일이 없으면 `git diff`로 전체 변경사항을 확인하고, 관련 파일을 스테이징

### 3. 커밋 메시지 작성

컨벤션에 따라 커밋 메시지를 작성합니다:
- 변경 내용을 분석하여 적절한 **type**과 **scope**를 결정
- subject는 동사로 시작, 50자 이내
- body에는 **왜** 이 변경이 필요한지 작성

### 4. 커밋 단위 판단

- 하나의 커밋은 하나의 논리적 변경 단위
- type이 다른 변경이 섞여 있으면 분리 커밋을 제안
  - 예: 스타일(`style`)과 기능(`feat`)은 별도 커밋
  - 예: i18n 추가(`i18n`)와 컴포넌트 구현(`feat`)은 별도 커밋

### 5. 실행

- 사용자에게 커밋 메시지를 보여주고 확인 후 커밋
